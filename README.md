# بوت توزيع عينات Red Dead Online

## المتطلبات
- Python 3.10 أو أحدث.
- بوت أنشأته عبر @BotFather.
- استضافة تدعم تشغيل Worker/Background Process وقرصاً دائماً (Persistent Disk).

## الإعداد على FadeHost
1. ارفع ملفات المشروع أو فك ضغط `rdo_distribution_bot.zip` في مشروع Python.
2. اجعل أمر التثبيت: `pip install -r requirements.txt`.
3. أضف متغير البيئة `BOT_TOKEN` في لوحة FadeHost والصق التوكن هناك فقط. لا تضعه في `bot.py` أو ترسله لأحد.
4. اجعل أمر التشغيل `python bot.py` أو استخدم `Procfile` إذا كانت الاستضافة تدعمه.
5. اربط `DB_PATH` بمسار على التخزين الدائم، مثال: `/data/bot.sqlite3`، وتأكد أن مجلد `/data` قابل للكتابة. لا تستخدم مساحة مؤقتة إذا كانت FadeHost تحذفها عند إعادة التشغيل.
6. في @BotFather نفّذ `/setprivacy` ثم اختر البوت ثم `Disable` حتى يستقبل ردود الأعضاء على رسائل القروب. أضف البوت للقروب وامنحه صلاحية إرسال الرسائل وقراءة الرسائل؛ يفضّل منحه صلاحية حذف/إدارة الرسائل فقط إذا احتجتها لاحقاً.
7. شغّل Worker واحداً فقط لهذا البوت لتجنب تشغيل نسختين تسحبان تحديثات Telegram نفسها.

## طريقة الاستخدام
- المشرف يرد على الرسالة المراد ربطها بالتوزيع بكلمة `توزيع`.
- العضو يرد على **الرسالة الأصلية نفسها** ويرسل ID اللعبة.
- المشرف يرسل `قائمة` لعرض قائمة أحدث توزيع نشط في القروب.
- المشرف يرسل `وقف توزيع` لإيقاف أحدث توزيع نشط وإصدار التقرير.
- المشرف يرسل رقم التسجيل كرسالة عادية لإرسال `وصل دورك اقبل وجون` رداً على رسالة تسجيل العضو الأصلية.

## ملاحظة مهمة عن تعدد التوزيعات
يمكن تشغيل عدة توزيعات مستقلة في القروب، والتسجيل مرتبط بمعرّف الرسالة الأصلية. أرقام التسجيل فريدة على مستوى القروب (وليست معاد استخدامها بين التوزيعات) حتى تكون رسالة الرقم العادية كافية لتحديد العضو دون التباس عند وجود توزيعين نشطين.

بما أن `قائمة` و`وقف توزيع` رسالتان عاديتان بلا رد أو معرّف توزيع، فهما تطبّقان على **أحدث توزيع نشط**. هذا يجعل السلوك حتمياً عند وجود عدة توزيعات. يمكن لاحقاً إضافة صيغة اختيار صريحة مثل `قائمة 12` و`وقف توزيع 12` إذا رغبت.

## الاختبارات
شغّل:
```bash
pip install -r requirements.txt
python -m unittest discover -s tests -v
```
الاختبارات تتحقق من استقلال التوزيعات، منع التكرار، إغلاق التسجيل، واستمرار البيانات في SQLite. وهي اختبارات محلية للمنطق وقاعدة البيانات، وليست اختبار اتصال مباشر مع Telegram.

## ملاحظات تشغيلية
- لا تشارك `BOT_TOKEN` في المحادثات أو ملفات المشروع.
- خذ نسخة احتياطية دورية من ملف SQLite.
- الرسائل الطويلة تقسم إلى دفعات لتفادي حد طول رسالة Telegram.
- التاريخ والوقت يخزنان بتوقيت UTC ويعرضان بتوقيت نظام الاستضافة.
